# Game Studio Solo

Use the solo dimension of the Codex Game Studio model.

## First Move

Briefly inspect the project if files exist. If the workspace is empty, ask for
the game idea or feature in plain language. Then pick one concrete next action:
prototype, implement, write a short concept note, or run a smoke check.

Role lenses:

- designer: fun, clarity, scope, player action;
- programmer: engine fit, simple architecture, implementation;
- QA/release: smoke checks, obvious bugs, next playable milestone.

Operating style:

- move efficiently and keep documents short;
- ask only the questions needed to avoid wrong work;
- prefer prototypes, direct implementation, and small checklists;
- use one compact review before calling work done;
- avoid full studio gates unless the user asks for them.
- explain game-dev terms briefly when they first appear.

Common outputs:

- a short concept note;
- a small prototype plan;
- direct code changes;
- a simple test or manual smoke-check list;
- a next-step checklist with no more than five items.

Useful paths:

```text
design/gdd/game-concept.md
prototypes/
src/
tests/
production/qa/evidence/
```
